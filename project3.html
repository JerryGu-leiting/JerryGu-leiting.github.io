Project 3 · Forward kinematics

A robot arm that dances from its own URDF

My runtime reads a robot description, works out where every link is from the joint angles, and streams those poses to a viewer. A finite state machine drives the joints through a choreography.

The robot

I designed a small arm for this video and described it in URDF. It uses only boxes, cylinders and spheres, so the viewer can draw it without mesh files. It has 13 links and 9 joints and uses all four joint types the project supports.

The choreography

The dance is a table of 15 states. Each state is a joint-space setpoint. When every joint is within 0.02 of its target, the state machine follows the state's on_arrival transition to the next one. After the last state it loops back to the start.

The first half is a pick-and-place: reach down, close the gripper, lift, swing the turntable around, and set the object down. The second half waves, spins half a turn, and bows.

How it works

Forward kinematics

The runtime parses the URDF itself, finds the root link, and walks the tree. Each joint's transform is T_origin · T_motion(q). Rotations are unit quaternions built directly from roll-pitch-yaw and axis-angle; no kinematics library is used. robot_state_publisher publishes every joint's transform on /tf. robot_world_state_publisher composes them from the root down and publishes each link's 4×4 pose on /xform_world at 10 Hz.

Motion

A joint_state_publisher node acts as the motors. It moves each joint toward its setpoint with a proportional servo, capped at the joint's velocity limit, so the arm speeds up and settles smoothly. The finite_state_machine node publishes each state's setpoint and watches /joint_states to decide when the arm has arrived.

Drawing it

The viewer is a three.js page. A small Python bridge connects to the runtime over TCP and forwards /xform_world to the browser with Server-Sent Events. The page builds one mesh per link from the URDF's visual shapes. On every update it copies each link's matrix straight into three.js, because /xform_world is column-major, the same layout Matrix4.fromArray reads. URDF is z-up and three.js is y-up, so the viewer rotates the whole scene by −90° about x. The orange lines are the kinematic skeleton, and the yellow line traces the tool tip.
